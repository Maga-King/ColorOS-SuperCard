# 运行状态与 PAY 设置

打开“超级卡包”的原生设置页，进入“运行状态与 PAY 设置”。自身设置兼容逻辑已内置到应用，不需要在框架中勾选卡包自身作为作用域；SystemUI 等运行目标仍需按模块要求启用。

页面适配浅色和深色主题，可点击“刷新运行状态”重新检测：

- **Root 授权**：后台实际执行 `su -c id`，只有命令成功且确认 `uid=0` 才显示已授权。最长等待 12 秒，分别显示未获授权、无法运行或超时；不会仅凭存在 `su` 判定可用，也不会每次返回页面重复请求授权。
- **框架 / SystemUI 激活**：向 SystemUI 中运行的卡包请求诊断，显示框架名称、版本和激活状态。未连接表示尚未取得有效响应，不能据此判断框架未安装。
- **虚拟屏后端**：显示 RootDisplay 后端是否已就绪。Root 授权成功与后端就绪是两个状态；后端就绪也不等于微信或支付宝页面已成功启动。

PAY 触摸白名单有九项：微信扫一扫、支付宝扫一扫、微信付款码、支付宝付款码、支付宝乘车码、微信乘车码、微信分身扫一扫、微信分身付款码、支付宝医保码。

全部默认关闭，关闭表示沿用原版触摸名单，原版允许的页面仍可触摸。开启某项后，只为当前虚拟屏中对应功能的目标应用页面追加触摸放行；认证页面及原版全屏处理仍由原逻辑负责。该设置不会改变支付业务、扫码或乘车码的跳转目标，也不会保证页面支持虚拟屏运行。

取得有效诊断前，开关不可操作。保存期间暂时禁用操作；保存未确认时恢复上次读取的显示，请点击刷新核对实际状态。设置保存后会保留，下次打开页面继续读取。

Vector 与 LSPosed 使用共用实现。本次已在 LSPosed 测试机验证设置页、权限自动配置和测试入口；Vector 尚未进行独立设备验收，真实微信、支付宝各功能的触摸和启动行为也尚未完成验证。

应用获得 Root 后会自动授予当前统一包声明且系统允许授予的运行时/开发权限，并允许写系统设置、悬浮窗、后台运行，加入电池优化白名单。LSP 中的 SystemUI 也会尝试使用已有权限授予这些声明权限。ColorOS 自启动、关联启动与后台运行通过系统自己的 provider 设置并读回确认；只处理超级卡包自身。状态页刷新会重新尝试，未知或系统不支持的结果不会标成成功。首次未取得设置保存权限时，设置页阻止继续编辑并显示重试，防止修改丢失。

PAY 编辑页隐藏不支持的显示账单开关，保留背景列表；皮肤加载器在独立设置进程初始化。有相机功能时保留正常 LENS 预览，空列表则显示所选背景和无可用功能提示。
