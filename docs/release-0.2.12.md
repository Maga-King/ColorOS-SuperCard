# 0.2.12-unified · versionCode 19

- 修复部分设备 PAY 虚拟屏创建失败：删除 root 后端额外添加的「虚拟屏 DPI 不得超过主屏」校验。反馈设备请求 480 DPI，系统资源为 474 DPI，旧校验在调用 Android 创建接口之前就拒绝了请求。
- 同时删除虚拟屏宽高不得超过主屏长边的限制，以及启动时读取并缓存主屏尺寸/DPI 的依赖。遵循 vivo 原版 `VirtualDisplayWrapper`，将卡片计算出的宽、高、DPI 原样传给系统；允许独立虚拟分辨率及原版付款码放大布局。
- 参数仍须为正数，继续校验调用方、会话、Surface 和安全显示标志。
- 修复 PAY 主动启动与后台退避的时间冲突：后台连续启动失败后会间隔 30 秒再试，点击卡片现在可以请求一次经过 3 秒节流的启动，不必等完整退避周期。重复普通请求也不再不断推迟已排队的启动。卡片关闭后的取消及单次等待超时继续生效。
- 修复小布记忆同一草稿连续三次写入前失败后无法手动重试的问题。每次保存的自动重试仍有限次；已发生写入、结果不确定或已产生记忆 ID 时不重放导入。

离线验证：57 项 PAY 用户路由、16 项启动时序、14 项实际编译类的记忆重试检查通过；补丁 DEX 再生一致，Gradle 编译、统一包资源与签名校验通过。与 0.2.11 相比，APK 内容仅宿主 `classes8.dex`、版本清单及签名项变化，原版资源和插件资产逐项一致。

已知问题：券码列表目前最多返回 100 张，且单次数据最多 180,000 字符；超出时会截断，包含较大二维码图片时可能在不到 100 张时触发。本版保留现有容量限制。详细说明见 [运行时限制审查](https://github.com/Maga-King/ColorOS-SuperCard/blob/v0.2.12/docs/runtime-limit-audit.md)。

反馈的真我设备尚未实测；需验证 PAY 页面显示、触摸及关闭卡片后的释放行为。覆盖安装后重启手机加载新版模块。
