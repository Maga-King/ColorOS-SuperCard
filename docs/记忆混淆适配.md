# 小布记忆混淆适配

## 实现范围

`MemoryImportBridge` 保留原生小布导入流程。混淆门禁首次按 DexKit 业务语义唯一定位，随后按类加载器缓存。不能仅凭旧名字和相同签名接受一个方法：17.3.0 的 `f0.P(): boolean` 已变成首页来源筛选状态，真正的服务开关是 `S()`。原方法调用抛错不会触发重新定位、重新导入或第二次写入。下表的旧版位置仅供对照，不再用作混淆名快捷路径。

| 入口 | 现有反射 | DexKit 后备依据与校验 |
| --- | --- | --- |
| 隐私协议开关 | `utils.p2.l(): boolean` | 同一方法引用 `SuperBreenoAuthorizationHelper` 与 `isMemoryPrivacyEnable: `；原包内、静态、零参数、boolean，候选必须唯一 |
| 服务开关 | `utils.f0.P(): boolean` | 零参数 boolean 方法调用默认参数函数，后者含 `breeno_memory_service_switch_enable` 且调用 `getMemoryServiceSwitchStatus ` / `AuthorizationUtils` 标记的 `int(String)` 读取函数；保留原 `P → t → s` 语义 |
| 网络验证状态 | `network.NetworkUtil.s(): boolean` | 保留未混淆的 `NetworkUtil` 类；唯一静态 volatile boolean 字段的直接读取，DEX 指令严格为 `sget-boolean, return`，字段写入来自接收 `NetworkCapabilities` 并调用 `hasCapability` 的本类方法；排除 synthetic 访问器，要求唯一 |
| 录音存储空间检查 | `voicecollect.utils.w` 内唯一静态 `boolean(long)` | `VoiceCollect-Utils`、`isStorageLow: ` 与完整 `boolean(long)` 签名，原包内静态方法，要求唯一 |
| 录音结果回调对象 | `voicecollect.collect.f` 的单例字段 | 从 `business.collection.voice` 包内调用原 handler 且读取 `TriggerType.VOICE_RECORD` 的协程反查；兼容旧 Fragment 与新版 `VoiceBottomBarController`。只接受调用现场读取的静态自身类型字段，且类型实现 handler 第六参数接口、非抽象类、只有一个自身类型静态单例字段；来源类型必须唯一 |
| JSON 序列化 | `GsonExtKt` 中静态 `String(Object,boolean)` | 旧稳定类名结构匹配失败时，以 `GsonExt`、`toJsonStr error, ` 和完整签名唯一定位，不写死新版混淆类名 |

DexKit 返回零个或多个符合条件的候选时，原入口保持不可用并报告错误，不取第一个。网络字段、原录音页面调用关系变化时同样停止适配，不替换成“有网络”“已授权”等常量。

## 保持原生的部分

`PortalImageUseCase`、`MemoryManualImport`、`DataShareProvider`、`VoiceRecorder`、`VoiceRecordResultHandler`、`DataStoreManager`、`PreprocessData`、`Attachment` 等现有未混淆类继续按类名和完整参数/返回类型解析。这些结构变化需要重新审核数据模型和写入协议，本次不推测其他类来代替。

原反射辅助函数曾在同返回类型的零参方法中取首个。现在读取仓库、记忆主体、图片 URI 时先选已确认语义的 `getMemoryRepository`、`getMemory`、`getUri`。Kotlin `componentN` 与 getter 同时存在时不会造成正常入口歧义；语义 getter 不存在时，只有唯一实例方法符合完整签名才接受，多个候选拒绝。不会调用一批未知 getter 来猜结果。

`voicecollect.utils.r` 的录音引导/旧协议/采集开关反射只用于诊断日志，不控制本次已有录音导入；它解析失败仍仅记录日志，未纳入必要入口的 DexKit 后备。

## 只读强制探针

直接调用：

```java
Bundle report = MemoryDexResolver.probe(aimemoryClassLoader, true);
```

也可以沿现有显式有序广播发送：

```java
Intent intent = new Intent(MemoryImportBridge.ACTION)
        .setPackage("com.oplus.aimemory")
        .putExtra("op", "probe")
        .putExtra("forceDexKit", true);
// 使用现有客户端 BroadcastOptions.setShareIdentityEnabled(true) 和有序结果接收器。
```

广播仅接受真实 UID、包名均匹配的 SystemUI 或宿主，与原导入鉴权相同；ADB shell 直接发广播不满足这个身份校验。不需要 guid、附件 URI 或导入授权。`forceDexKit=true` 直接执行六项语义查询并共享一个索引，不读取或修改生产缓存；图片契约另行检查。

成功返回 `status=probe_ok, ok=true`，对应有序广播 `RESULT_OK`。各入口返回解析的方法签名或回调类名；失败返回 `status=probe_failed` 和 `<role>Error`，索引本身失败为 `dexkitError`。六个 role 为 `privacy/service/network/storage/voiceCallback/jsonSerializer`；另有 `imageContract/imageImport/imageSave/imageModel/imageCompletion`，图片契约失败为 `imageContractError`。

探针不执行解析所得的开关/导入/回调方法，不读取单例字段的值，不创建导入任务，不读写记忆数据库或 HISTORY。普通 `op=check` 仍会读取原开关的真实值，含义与探针不同。

## 防止重复保存

本次没有修改 Job 的写入标记、完成相关性或重试判定。图片 Provider call、录音 handler、文档 manualImport 的原写入口仍先标记 `writeAttempted`。只有确认尚未尝试任何写入、没有原生完成信号、没有保存 ID 的失败才允许现有兜底重试；解析后原方法抛错或写入结果未知不能借后备解析再次写入。
