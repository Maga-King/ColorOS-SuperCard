# APK 产物一致性

`tools/compare_apk.py` 仅使用 Python 标准库，支持 Python 3.10 及以上版本。它核对本地与 GitHub Actions 产物的 ZIP 解压内容，输出 JSON 和中文摘要。

## 直接比较两个 APK

```sh
python tools/compare_apk.py compare local.apk actions.apk --output comparison.json
```

JSON 输出到标准输出，中文摘要输出到标准错误。提供 `--output` 时同时写入 UTF-8 JSON 文件，输出目录须已存在。

退出码：

- `0`：所比较的内容一致。
- `1`：项名、解压大小或解压内容 SHA256 存在差异。
- `2`：文件读取失败、ZIP 损坏、存在重复项或参考指纹无效；不能视为比较成功。

报告列出仅左侧存在、仅右侧存在和内容变化的项，也分别记录两个 APK 文件本体的 SHA256。文件本体哈希不同并不必然表示解压内容不同。

## 本地指纹与 CI 验证

先针对本地认可的确切 APK 生成参考文件：

```sh
python tools/compare_apk.py fingerprint local.apk --output local-apk-fingerprint.json
```

CI 构建完成后使用同一参考文件：

```sh
python tools/compare_apk.py compare actions.apk --reference local-apk-fingerprint.json --output comparison.json
```

参考指纹包含按 ZIP 项名排序的 `entries`，每项记录 `name`、解压后 `size` 和 `sha256`。`payloadSha256` 是以下 ASCII 字节的 SHA256：

```text
apk-uncompressed-entries-v1\n
```

其中 `\n` 表示一个 LF 换行字节。上述前缀后紧接 `entries` 的规范 JSON：Python `json.dumps(entries, ensure_ascii=True, sort_keys=True, separators=(",", ":"))`，不附加尾部换行。

APK 在电脑上的文件路径、参考文件路径、ZIP 时间戳、项排列和压缩方法均不进入 payload 哈希；ZIP 内部项名进入哈希，用于检出重命名与缺失文件。文件本体 SHA256 单独保存在 `source.fileSha256`，不决定 payload 是否一致。

工具读取参考文件时会重新计算 payload 哈希并校验条目结构、顺序和重复项。参考文件本身也有 SHA256 记录，但这些校验不能证明参考文件来源可信。参考指纹必须对应用户认可的本地产物，不能用刚构建的 CI APK 生成指纹后再与自己比较。

## 精确排除范围

只排除下列 APK 签名相关 ZIP 项，名称匹配不区分大小写：

- `META-INF/MANIFEST.MF`。
- `META-INF/` 的直接子项，且扩展名为 `.SF`、`.RSA`、`.DSA` 或 `.EC`。

APK v2/v3 等签名块不属于 ZIP 项，天然不进入 ZIP payload 对比。其他元数据全部参与对比，包括 `META-INF/xposed/*`、服务描述、版本标记和嵌套插件 APK。`META-INF/services/example.RSA` 这样的嵌套路径也不会被当作签名项排除。

所有 ZIP 项均先检查重名，包括准备排除的签名项。出现重复项立即报错，避免不同 ZIP 读取器选择不同副本。目录项同样参与对比。嵌套 APK 按其完整文件字节比较，其内部签名差异也会被检出。

## 能证明什么

payload 一致说明上述规则覆盖的 ZIP 项名和解压内容一致；文件本体 SHA256 一致进一步说明整个 APK 字节一致。工具不比较压缩方式、ZIP 对齐与签名块，也不验证签名证书、签名有效性或来源。

哈希一致不能证明实机功能正常。系统版本、Vector 作用域、权限、账号、root 后端、安装状态与运行时数据都会影响行为。原资源 ID 是否正确、设置是否可启动、付款容器和记忆导入是否可用，需要另外的构建检查或实机证据。Release 的签名和升级兼容性也应另行核对。

自测命令会只在临时目录创建两个 ZIP，验证一致、差异、参考指纹和重复项处理：

```sh
python tools/compare_apk.py self-test
```
